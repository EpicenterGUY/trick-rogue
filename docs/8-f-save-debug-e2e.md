# 8-F 저장 / 디버그 / E2E 기반

## 저장 경계

- 자동 저장은 런의 안전 체크포인트에서만 수행한다.
- 전투 진행 중에는 저장하지 않는다.
- 이벤트/캠프/상점 등 노드 처리 중(`currentNodeId`가 남아 있는 동안)에도 저장하지 않는다.
- 전투 진입 전 마지막 맵 체크포인트는 유지하므로 앱을 다시 열면 해당 안전 지점부터 재개한다.
- 런 승리/패배 시 저장은 삭제한다.

## 저장 포맷

- 포맷 ID: `tricklog-run-save`
- 현재 버전: `1`
- 런 진행에 쓰이는 `Set`/`Map`을 타입 태그가 있는 JSON으로 직렬화한다.
- payload 체크섬을 저장해 손상되거나 임의 변경된 저장은 적용 전에 차단한다.
- 현재 버전보다 미래 버전인 저장은 거부한다.
- 포맷이 없던 구버전 plain JSON 런을 v1로 올리는 마이그레이션 입구를 제공한다.
- 불러오기 시 `available`/`completed`를 다시 `Set`으로 복원하고, 저장된 낡은 카드 정의 참조는 가능한 경우 현재 카드 레지스트리 정의로 다시 연결한다.

## 브라우저 동작

- 저장이 있을 때 시작 화면에 `계속하기` 버튼을 추가한다.
- `renderMap`, `beginRun`, `completeNode`의 최신 래퍼 체인 뒤에서 안전 체크포인트를 자동 저장한다.
- 복구 시 현재 battle을 비우고 저장된 런을 전역 런 상태에 되돌린 뒤 맵을 다시 렌더한다.
- 지역 선택 단계에서 저장된 경우 맵 복구 후 지역 선택 UI를 다시 연다.

## 디버그

- 일반 플레이에서는 디버그 패널을 숨긴다.
- URL에 `?debug=1`을 붙이거나 `TRICKLOG_DEBUG=true`를 명시한 경우에만 DEBUG 패널을 연다.
- 패널에서 현재 시드, 런 지문, 액트/지역 진행, HP/골드/덱, 전투 세트/트릭/트럼프/칩/슬롯/리버 등을 확인한다.
- 저장/불러오기/저장 삭제/스냅샷 복사를 지원한다.

## 결정적 재현

- 기존 `runSeed`를 저장 포맷에 보존한다.
- 맵/지역 계획 재현을 위해 런의 결정적 핵심 상태를 정규화한 `runFingerprint()`를 제공한다.
- 저장 직전과 복구 직후의 런 지문이 같은지 `verifyRoundTrip()`으로 확인할 수 있다.

## E2E 기반

- `npm run test:e2e`
- 같은 시드의 맵 변형이 저장 전후에도 동일한지 확인한다.
- 최신 양측 쇼다운 선공/반격 취소 흐름을 실제 계산기로 통과시킨 뒤 전투 종료 체크포인트 저장/복구까지 확인한다.
- 체크섬이 깨진 저장이 정상 런을 덮어쓰기 전에 차단되는지 확인한다.
